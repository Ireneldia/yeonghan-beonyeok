## A. 큰 그림 용어

### 백엔드 / 프런트엔드 (Backend / Frontend)

**1. 유래.** "front end"와 "back end"는 원래 1960~70년대 대형 컴퓨터 용어다. 사용자가 직접 만지는 단말기 쪽이 앞(front), 실제 계산과 저장을 하는 본체 쪽이 뒤(back). 웹으로 넘어오면서 브라우저에서 돌아가는 화면 코드를 프런트엔드, 서버에서 돌아가는 처리·저장 코드를 백엔드라고 부르게 됐다. 언어가 아니라 **역할**을 가리키는 말이다.

**2. 어디서 쓰나.** 거의 모든 소프트웨어 회사가 "프런트엔드 개발자", "백엔드 개발자"로 직무를 나눈다.
- 프런트엔드: 네이버·카카오 웹 화면, 토스 앱 화면. 증권사에서는 MTS(모바일 트레이딩 시스템)·HTS 화면 개발 직무.
- 백엔드: 주문을 받아 처리하고 DB에 넣는 서버. 증권사에서는 **계정계(원장) 시스템**, 주문·체결 서버, 시세 분배 서버가 대표적인 백엔드이고, 지연이 밀리초 단위로 중요해서 C/C++·Java가 많다.

**3. 이 프로젝트에서.** `frontend/` 폴더(브라우저에서 도는 HTML·JS·CSS)가 프런트엔드, `backend/` 폴더(Python)가 백엔드다. 둘은 HTTP로만 대화한다. 예를 들어 단어를 클릭하면 프런트가 백엔드에 요청을 보낸다.

```js
// frontend/app.js — 프런트: 서버에 "이 단어 뜻 찾아줘"
const l = await api(`/api/docs/${S.doc.id}/lookup`, {
  method: 'POST', body: JSON.stringify({ page: S.page, kind: 'word', text, word_ids: ids })
});
```
```python
# backend/app.py — 백엔드: 요청을 받아 DB에 넣고 큐에 올림
@app.post("/api/docs/{doc_id}/lookup")
async def lookup(doc_id: str, body: LookupIn):
    lid = db.add_lookup(doc_id, body.page, body.kind, text, body.word_ids)
    await queue.put(lid)
    return db.find_lookup(doc_id, body.page, body.kind, text)
```

### 프레임워크 (Framework)

**1. 유래.** frame(뼈대) + work(구조물). 건축에서 골조를 뜻하던 말이 1980년대 객체지향 프로그래밍에서 "미리 짜인 뼈대에 내 코드를 끼워 넣는 라이브러리"라는 뜻이 됐다. 라이브러리와의 차이는 **제어의 역전**: 라이브러리는 내가 부르고, 프레임워크는 프레임워크가 내 코드를 부른다. 이걸 "할리우드 원칙(Don't call us, we'll call you)"이라고 한다.

**2. 어디서 쓰나.**
- 백엔드: Spring(Java) — 한국 증권사·은행 서버의 사실상 표준. Django·FastAPI(Python), Express·NestJS(Node.js).
- 프런트엔드: React, Vue, Svelte. 토스·카카오 화면은 React. 증권사 MTS도 요즘은 React Native나 웹뷰+React가 많다.
- 직무: 백엔드 개발자는 채용 공고에 "Spring 경험"이 거의 빠지지 않는다. 증권 IT의 오픈 API 팀·MTS 팀도 마찬가지.

**3. 이 프로젝트에서.** 백엔드는 FastAPI라는 프레임워크를 쓴다. 내가 `@app.post(...)`로 함수를 등록하면 요청이 올 때 FastAPI가 그 함수를 불러준다. 프런트엔드는 프레임워크 없이 순수 JS다. 개인 도구라 화면이 단순해서 React까지 필요 없었다.

```python
# backend/app.py — 프레임워크가 내 함수를 부르는 구조
app = FastAPI(title="영한번역")

@app.get("/api/docs")          # "이 주소로 GET 요청이 오면 아래 함수를 불러라"
def list_docs():
    return db.docs()
```

### 번들러 (Bundler)

**1. 유래.** bundle = 묶음. 프런트엔드 코드가 수십~수백 개 파일로 커지자 그걸 한두 개로 묶고(bundle), 압축하고, 최신 문법을 옛 브라우저용으로 바꿔주는 도구가 생겼다. Browserify(2011), webpack(2012), Vite(2020, 프랑스어로 "빠르다").

**2. 어디서 쓰나.** React·Vue 프로젝트는 거의 예외 없이 번들러를 쓴다. 대부분 Vite 또는 webpack. 프런트엔드 개발자 직무의 기본 도구다. 증권사 MTS 웹 화면 팀도 같다.

**3. 이 프로젝트에서.** **안 쓴다.** `frontend/index.html`이 `app.js`와 `style.css`를 그대로 읽는다. 파일이 세 개뿐이라 묶을 게 없고, 빌드 단계가 없어서 고치고 새로고침하면 바로 반영된다. 표에 "번들러 없음"이라고 쓴 건 이 뜻이다.

```html
<!-- frontend/index.html — 번들 없이 원본 파일을 바로 읽는다 -->
<link rel="stylesheet" href="style.css">
<script src="app.js"></script>
```

### REST API

**1. 유래.** API는 Application Programming Interface, "프로그램끼리 대화하는 약속". 1968년 논문에서 처음 쓰였다. REST는 REpresentational State Transfer, 2000년 로이 필딩(Roy Fielding)의 박사 논문에서 나왔다. 그는 HTTP 규격을 만든 사람 중 하나로, "웹이 잘 돌아가는 이유"를 원칙으로 정리했다. 핵심은 **주소(URL)가 자원을 가리키고, 동사(GET/POST/PUT/DELETE)가 할 일을 가리킨다**는 것.

**2. 어디서 쓰나.** 거의 모든 웹 서비스의 서버 통신 방식. 
- 증권 IT에서 가장 직접적인 예: **한국투자증권 KIS Developers**, **키움 REST API** — 계좌 조회, 주문, 시세를 REST로 제공한다. 자동매매 프로그램·핀테크 앱이 이걸로 증권사와 대화한다. 증권사 오픈 API 팀이 이걸 만들고 운영한다.
- 백엔드 개발자 직무 전반. "REST API 설계 경험"은 채용 공고 단골.

**3. 이 프로젝트에서.** 백엔드의 모든 기능이 REST API다. 주소로 자원을, 동사로 행동을 나타낸다.

| 동사 | 주소 | 뜻 |
|---|---|---|
| GET | `/api/docs` | 교안 목록 |
| POST | `/api/docs` | 교안 업로드 |
| GET | `/api/docs/{id}/page/12/meta` | 13쪽 단어 좌표 |
| POST | `/api/docs/{id}/lookup` | 조회 요청 |
| DELETE | `/api/lookups/{id}` | 조회 삭제 |
| PUT | `/api/questions/{id}` | 질문 수정 |

```python
# backend/app.py
@app.delete("/api/lookups/{lid}")
def del_lookup(lid: int):
    db.delete_lookup(lid); return {"ok": True}
```

### 정적 파일 (Static files)

**1. 유래.** static(정지한) ↔ dynamic(움직이는). 요청할 때마다 내용이 바뀌는 페이지(동적)와 달리, 누가 언제 요청해도 같은 파일(HTML·CSS·JS·이미지)을 정적 파일이라 부른다. 1990년대 초 웹은 전부 정적이었고, CGI(1993)가 나오면서 동적 페이지가 생겼다.

**2. 어디서 쓰나.** 모든 웹사이트. 보통 Nginx 같은 웹서버나 CDN(Cloudflare, AWS CloudFront)이 정적 파일을 담당한다. 인프라·DevOps 직무 영역. 증권사도 MTS 화면 리소스를 CDN으로 배포한다.

**3. 이 프로젝트에서.** 별도 웹서버 없이 FastAPI가 `frontend/` 폴더를 정적 파일로 그대로 내보낸다. 브라우저 캐시 때문에 고친 게 안 보이는 일이 있어서 `no-cache` 헤더를 붙였다.

```python
# backend/app.py — 마지막 줄. /api/ 가 아닌 주소는 전부 frontend/ 폴더의 파일
app.mount("/", StaticFiles(directory=os.path.join(ROOT, "frontend"), html=True), name="fe")
```

### ASGI 서버

**1. 유래.** 뿌리는 1993년 CGI(Common Gateway Interface, 웹서버와 프로그램 사이의 "관문" 규격). Python은 2003년 WSGI(Web Server Gateway Interface)를 만들어 "웹서버와 Python 앱이 대화하는 표준"을 정했다. WSGI는 한 번에 한 요청만 처리하는 동기 방식이라, 2016년 Django Channels 팀이 비동기(Async) 버전인 **ASGI**를 만들었다. "ASGI 서버"는 이 규격대로 앱을 실행해주는 프로그램이고, Uvicorn이 그중 하나다.

**2. 어디서 쓰나.** FastAPI·Django(비동기 모드)·Starlette 앱은 전부 ASGI 서버 위에서 돈다. Uvicorn, Hypercorn, Daphne. 백엔드·인프라 직무. 증권 IT에서는 Python 서비스(시세 알림, 데이터 파이프라인, 사내 도구)를 띄울 때 쓴다.

**3. 이 프로젝트에서.** `run.sh`가 Uvicorn으로 `app.py`의 `app` 객체를 띄운다. `--reload`는 코드를 고치면 자동 재시작.

```zsh
# run.sh
exec python3 -m uvicorn app:app --host 127.0.0.1 --port 8766 --reload
```

### 큐 / 워커 (Queue / Worker) — "번역 큐, 워커 3"

**1. 유래.** queue는 프랑스어로 "꼬리", 라틴어 cauda. 영국에서 "줄 서기"를 뜻하게 됐고, 컴퓨터에서는 **먼저 들어온 것이 먼저 나가는(FIFO) 대기줄**. worker는 말 그대로 일꾼: 큐에서 일감을 하나씩 꺼내 처리하는 실행 단위.

**2. 어디서 쓰나.** "지금 당장 답 안 줘도 되는 일"을 뒤로 넘길 때. 이메일 발송, 영상 인코딩, 결제 후처리.
- 도구: Celery+RabbitMQ(Python), Kafka(대용량 스트림), AWS SQS.
- 증권 IT: **주문 큐**가 핵심이다. 수천 건의 주문이 동시에 들어오면 큐에 쌓아 순서대로 체결 엔진에 넘긴다. 시세 분배도 Kafka 같은 메시지 큐로 한다. 계정계·체결 시스템 개발 직무.

**3. 이 프로젝트에서.** 단어를 클릭하면 바로 답이 오지 않는다(LLM 호출에 8~15초). 그래서 요청을 큐에 넣고 바로 돌아가 계속 읽을 수 있게 했다. 워커 3개가 큐에서 꺼내 처리하므로 동시에 3건까지 번역된다.

```python
# backend/app.py
queue: asyncio.Queue = asyncio.Queue()

async def worker():
    while True:
        lid = await queue.get()          # 대기줄에서 하나 꺼냄
        try:
            res = await loop.run_in_executor(pool, llm.word_meaning, ...)
            db.set_result(lid, result=res)
        finally:
            queue.task_done()

@app.on_event("startup")
async def _start():
    for _ in range(3):                   # 워커 3개
        asyncio.create_task(worker())
```

### CPU 작업 분리 (ThreadPoolExecutor)

**1. 유래.** 프로그램이 기다리는 일에는 두 종류가 있다. **I/O 대기**(네트워크·디스크 응답 기다리기)와 **CPU 작업**(계산 자체가 오래 걸림). asyncio는 I/O 대기에 강하지만, CPU를 오래 쓰는 작업이 끼면 전체가 멈춘다. 그래서 그런 작업은 별도 스레드 풀(thread pool, "실 묶음")로 보낸다. `ThreadPoolExecutor`는 Python 3.2(2011)에 들어온 표준 도구.

**2. 어디서 쓰나.** 이미지 처리, PDF 변환, ML 추론을 웹 서버에서 돌릴 때. 백엔드·ML 엔지니어 직무. 증권 IT에서는 리스크 계산·백테스트처럼 오래 걸리는 계산을 API 응답과 분리할 때 같은 패턴을 쓴다.

**3. 이 프로젝트에서.** Whisper 받아쓰기와 `claude -p` 호출은 몇 초씩 걸린다. 이걸 그냥 부르면 그동안 서버가 다른 요청(페이지 넘기기 등)에 응답을 못 한다. 그래서 스레드 풀로 보낸다.

```python
# backend/app.py
pool = ThreadPoolExecutor(max_workers=3)
...
raw = await loop.run_in_executor(pool, stt.transcribe, tmp, terms)   # 받아쓰기는 다른 스레드에서
```

### 단일 사용자 (Single-user)

**1. 유래.** 1960년대 시분할(time-sharing) 시스템이 나오기 전 컴퓨터는 한 번에 한 사람만 썼다. 지금은 반대로 "여러 사용자·여러 회사가 한 서버를 나눠 쓰는" 멀티테넌트(multi-tenant)가 기본이라, 그 반대말로 단일 사용자를 쓴다.

**2. 어디서 쓰나.** 개인 도구, 로컬 앱, 데스크톱 프로그램. 반대편의 멀티테넌트 설계(로그인, 권한, 사용자별 데이터 격리)는 백엔드·보안 직무의 핵심이고, 증권사는 고객 계좌 데이터 격리 때문에 특히 엄격하다.

**3. 이 프로젝트에서.** 로그인이 없다. DB에 사용자 컬럼이 없고, `127.0.0.1`(내 컴퓨터 안)에서만 듣기 때문에 밖에서 접속할 수 없다. 여러 명이 쓰게 하려면 로그인과 사용자별 데이터 분리를 추가해야 한다.

```python
# backend/db.py — 사용자 구분 없이 교안·조회만 저장
CREATE TABLE IF NOT EXISTS docs(id TEXT PRIMARY KEY, name TEXT, subject TEXT, path TEXT, pages INT, created REAL);
```

### 포트 8766 (Port)

**1. 유래.** port = 라틴어 portus(항구). 한 컴퓨터(IP 주소)가 여러 서비스를 동시에 하려면 문이 여러 개 필요한데, 그 문 번호가 포트(0~65535). 1980년대 TCP/IP 규격에서 정해졌다. 80(HTTP)·443(HTTPS)·22(SSH)처럼 유명한 번호는 IANA가 관리하고, 8000 이상은 개발용으로 자유롭게 쓴다.

**2. 어디서 쓰나.** 모든 네트워크 프로그램. 인프라·보안 직무는 방화벽에서 포트를 열고 막는 게 일상이다. 증권 IT에서는 HTS·MTS가 증권사 서버의 특정 포트로 접속하고, 거래소(KRX) 연계 회선도 포트 단위로 방화벽을 관리한다.

**3. 이 프로젝트에서.** 8766번 문에서 요청을 기다린다. 원래 8765를 쓰려 했는데 다른 프로젝트 서버가 쓰고 있어서 하나 올렸다. 브라우저 주소 `http://localhost:8766`의 8766이 그것.

```json
// .claude/launch.json
"runtimeArgs": ["-m", "uvicorn", "app:app", "--host", "127.0.0.1", "--port", "8766", ...],
"port": 8766
```

## B. 언어

### Python

**1. 유래.** 1991년 귀도 반 로섬(Guido van Rossum)이 네덜란드 CWI에서 만든 언어. 이름은 뱀이 아니라 영국 코미디 "Monty Python's Flying Circus"에서 따왔다. 그래서 공식 문서 예제에 spam, eggs가 자주 나온다. "읽기 쉬운 코드"가 설계 목표.

**2. 어디서 쓰나.** 데이터 분석·AI(PyTorch, pandas), 백엔드(Django, FastAPI), 자동화 스크립트. 
- 직무: 데이터 사이언티스트, ML 엔지니어, 백엔드 개발자.
- 증권 IT: **퀀트·리서치 직무의 표준 언어**. 백테스트, 리스크 계산, 시세 데이터 분석. 미래에셋·NH 등의 데이터 팀, 그리고 KIS Developers 예제 코드도 Python이다.

### FastAPI

**1. 유래.** 2018년 세바스티안 라미레스(Sebastián Ramírez)가 만든 Python 웹 프레임워크. 이름은 "코드를 빠르게 짜고(fast to code), 빠르게 돈다(fast performance)". Starlette(비동기 웹 툴킷)와 Pydantic(데이터 검증) 위에 얹었다. 함수의 타입 힌트만 보고 요청 검증·문서(Swagger)를 자동으로 만든다.

**2. 어디서 쓰나.** Uber, Netflix(ML 서비스), Microsoft가 사내에서 쓴다. ML 모델을 API로 감쌀 때 사실상 표준. 
- 직무: 백엔드(Python), ML 엔지니어.
- 증권 IT: 퀀트 팀이 만든 모델을 사내 서비스로 노출할 때, 시세·뉴스 분석 API.

**3. 이 프로젝트에서.** 요청 본문을 `BaseModel` 클래스로 선언하면 검증까지 자동. `http://localhost:8766/docs`에 들어가면 자동 생성된 API 문서도 볼 수 있다.

```python
# backend/app.py
class LookupIn(BaseModel):     # 요청 본문 형식. 안 맞으면 FastAPI가 알아서 400 오류
    page: int
    kind: str
    text: str
    word_ids: list[int] = []
```

### Uvicorn

**1. 유래.** "uv" + "unicorn". uv는 libuv/uvloop(고속 비동기 I/O 라이브러리), unicorn은 앞선 WSGI 서버 Gunicorn("Green Unicorn")에서 따온 말장난. 2017년 Tom Christie(Starlette·Django REST framework 개발자)가 만들었다.

**2. 어디서 쓰나.** FastAPI 앱 실행의 기본값. 운영에서는 Gunicorn이 Uvicorn 워커 여러 개를 관리하는 형태로 많이 띄운다. 백엔드·인프라 직무.

**3. 이 프로젝트에서.** 위 ASGI 서버 항목 참고. `run.sh`와 `.claude/launch.json` 두 곳에서 부른다.

### asyncio

**1. 유래.** 2014년 Python 3.4에 들어온 비동기 표준 라이브러리. 원래 이름은 "Tulip"(귀도가 네덜란드 사람이라 튤립). async(비동기)+io. `async`/`await` 문법은 3.5(2015)에서 추가됐다.

**2. 어디서 쓰나.** 동시에 수천 개 연결을 다루는 서버, 크롤러, 채팅. 증권 IT에서 **실시간 시세 수신**(웹소켓으로 초당 수천 틱)이 전형적인 asyncio 용도다.

**3. 이 프로젝트에서.** 큐와 워커. 위 "큐 / 워커" 항목의 코드.

## E. AI / ML

### Claude Code CLI (`claude -p`)

**1. 유래.** Anthropic이 2025년 낸 터미널용 AI 코딩 도구. CLI는 Command Line Interface(명령줄 인터페이스). `-p`는 print 모드로, 대화창 없이 질문 하나를 주고 답만 받아 종료한다. 이걸 "헤드리스(headless, 머리 없는 = 화면 없는)"라고 부른다.

**2. 어디서 쓰나.** 개발자가 코드 작성·리뷰·자동화에 쓴다. 헤드리스 모드는 CI 파이프라인이나 스크립트에서 LLM을 부를 때.

**3. 이 프로젝트에서.** Anthropic API 대신 이걸 부른다. 구독에 포함이라 추가 비용이 없다. `subprocess`로 명령을 실행하고 표준 출력을 받는다. API로 바꾸려면 이 함수 하나만 고치면 된다.

```python
# backend/llm.py
def ask(prompt, system=SYSTEM, timeout=120, model=None):
    cmd = [CLAUDE, "-p", "--model", model or MODEL, "--output-format", "text",
           "--no-session-persistence", "--tools", "", "--system-prompt", system, prompt]
    r = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout, cwd=WORKDIR)
    return r.stdout.strip()
```

### PyMuPDF (MuPDF)

**1. 유래.** MuPDF는 Artifex가 2005년부터 만든 초경량 PDF 엔진. Mu는 그리스 문자 μ(마이크로, 작다는 뜻). PyMuPDF는 2015년 Jorj McKie가 만든 Python 바인딩. 모듈 이름이 `fitz`인 이유는 Artifex가 MuPDF의 그래픽 엔진을 "Fitz"라고 불렀기 때문.

### rapidfuzz

**1. 유래.** fuzzy(흐릿한) 문자열 비교 = "완전히 같지 않아도 얼마나 비슷한가"를 점수로. 바탕은 1965년 러시아 수학자 레벤슈타인(Levenshtein)의 편집 거리(한 글자씩 고쳐서 같게 만드는 횟수). 2011년 SeatGeek이 FuzzyWuzzy를 냈고, 2020년 Max Bachmann이 C++로 다시 써서 훨씬 빠른 rapidfuzz를 냈다.

**2. 어디서 쓰나.** 오타 있는 검색, 주소·이름 매칭, 중복 제거. 데이터 엔지니어 직무. 증권 IT에서는 **종목명 매칭**("삼성전자우"와 "삼성전자 우선주"), 고객 이름 대조(KYC), 뉴스에서 회사명 찾기에 쓴다.

**3. 이 프로젝트에서.** 음성 인식이 "bread first"라고 잘못 적어도 페이지 단어 "Breadth-First"와 가장 비슷한 것을 고른다.

```python
# backend/match.py
r = process.extractOne(tok, choices, scorer=Levenshtein.normalized_similarity)
if r and r[1] >= 0.6: ...   # 유사도 60% 이상이면 채택
sc = fuzz.token_set_ratio(q, st) / 100.0   # 문장은 단어 겹침 비율
```

**1. 유래.** Anki(暗記)는 일본어로 "암기". 2006년 Damien Elmes가 일본어 공부용으로 만든 간격 반복 카드 프로그램. 알고리즘은 1987년 폴란드 Piotr Woźniak의 SuperMemo SM-2. genanki는 2017년 Kerrick Staley가 만든 "Python으로 Anki 덱 파일(.apkg) 생성" 라이브러리.

### SQLite

**1. 유래.** 2000년 D. Richard Hipp가 미 해군 구축함 소프트웨어를 만들다가 "설치 없이 파일 하나로 되는 DB"가 필요해서 만들었다. Lite는 서버형 DB(MySQL, Oracle)와 달리 가볍다는 뜻. 세상에서 가장 많이 배포된 DB 엔진이다. 모든 스마트폰, 모든 브라우저, 에어버스 항공기에 들어 있다.

**2. 어디서 쓰나.** 앱 내부 저장소(카카오톡 메시지 캐시), 설정 파일, 프로토타입. 서비스 규모가 커지면 PostgreSQL·MySQL로 옮긴다. 증권 IT에서는 HTS 클라이언트의 로컬 캐시(관심종목, 차트 설정)에 쓰이고, 계정계 원장은 Oracle·Tibero 같은 대형 DB다.

**3. 이 프로젝트에서.** `data/yh.sqlite` 파일 하나에 교안·조회·질문이 다 들어 있다. 서버 설치 없이 Python 표준 라이브러리로 바로 쓴다.

```python
# backend/db.py
def add_lookup(doc_id, page, kind, text, word_ids):
    with conn() as c:
        cur = c.execute("INSERT INTO lookups(doc_id,page,kind,text,word_ids,status,created) VALUES(?,?,?,?,?,'pending',?)",
                        (doc_id, page, kind, text, json.dumps(word_ids), time.time()))
        return cur.lastrowid
```

### JSON 파일 캐시

**1. 유래.** JSON = JavaScript Object Notation. 2001년 Douglas Crockford가 JS 객체 표기법을 그대로 데이터 교환 형식으로 쓰자고 제안했다. XML보다 짧아서 REST API의 표준 형식이 됐다. cache는 프랑스어 "숨기다"에서 온 말로, 계산 결과를 저장해 두고 다시 쓰는 것.

**3. 이 프로젝트에서.** 페이지에서 단어 좌표를 뽑는 게 0.1초쯤 걸려서, 한 번 뽑으면 `data/docs/<id>.p<쪽>.json`에 저장해 두고 다음부턴 읽기만 한다.

## G. 인프라·도구

### localhost

**1. 유래.** "이 컴퓨터 자신"을 가리키는 이름. IP 주소로는 127.0.0.1. 1980년대 TCP/IP 규격에서 127.x.x.x 대역을 자기 자신(loopback, 되돌아오는 회선)용으로 정했다.

**2. 어디서 쓰나.** 모든 개발자가 서버를 자기 컴퓨터에서 먼저 띄워 볼 때. 

**3. 이 프로젝트에서.** `--host 127.0.0.1`이라 같은 Wi-Fi의 다른 기기에서도 접속이 안 된다. 개인 도구라 일부러 그렇게 했다.

### Google Drive 데스크톱

**3. 이 프로젝트에서.** 내보낸 PDF를 `data/exports/`에 저장하는데, 이 폴더를 Drive 동기화 폴더 안에 두면 갤럭시 탭에서 바로 열린다. 프로그램이 Drive API를 부르지 않고 파일만 저장하므로 설정이 필요 없다.

### git / `.claude/launch.json`

**1. 유래.** git은 2005년 리누스 토발즈가 리눅스 커널 소스 관리용으로 **2주 만에** 만들었다. 이름은 영국 속어로 "얼간이". 리누스가 "내 프로젝트 이름은 다 내 이름을 따서 짓는다"고 농담한 데서 왔다. GitHub(2008)는 git 저장소를 올려두는 서비스.
`launch.json`은 VS Code가 만든 "이 프로젝트 실행법" 설정 파일 이름이고, Claude Code도 같은 이름을 쓴다.

**2. 어디서 쓰나.** 모든 개발 직무. 증권사도 사내 GitLab/Bitbucket으로 코드를 관리하고, 배포 승인 절차(형상관리)가 금융 규제 요건이다.

**3. 이 프로젝트에서.** 커밋 4개. `.gitignore`로 교안 PDF·번역 DB·1.6GB 모델은 저장소에서 뺐다. `launch.json`은 개발 서버를 자동 재시작 옵션으로 띄우는 설정.

```
# .gitignore
data/
__pycache__/
.DS_Store
교안 샘플/
```
